SOURCE VERSION

SOURCE RECORD

Rows retain provenance

SAVED REVISION

Reviewable history

Inspect the latest-revision reporting query · SQL

This new illustrative query ranks saved revisions per day and joins the selected revision to its originating schedule. Bound period parameters keep values separate from SQL syntax.

-- Bound parameters keep the requested period separate from SQL syntax.
-- Rank revisions within each roster day, then attach schedule provenance.
WITH ranked AS (
    SELECT id, saved_at_utc, payload_json,
           json_extract(payload_json, '$.date') AS roster_date,
           ROW_NUMBER() OVER (
               PARTITION BY json_extract(payload_json, '$.date')
               ORDER BY saved_at_utc DESC, id DESC
           ) AS revision_rank
    FROM roster_revisions
)
SELECT r.id, r.roster_date, r.saved_at_utc, s.source_file,
       json_extract(r.payload_json, '$.routeTarget') AS route_target
FROM ranked AS r
LEFT JOIN roster_schedule_sources AS s
  ON s.source_hash = json_extract(r.payload_json, '$.scheduleHash')
WHERE r.revision_rank = 1
  AND r.roster_date BETWEEN :start_date AND :end_date
ORDER BY r.roster_date;

02 / VALIDATION AND AUTOMATION

A date selection must not weaken source checks.

The simplified Python example applies the same metadata checks whether a reporting Sunday is inferred or selected explicitly. It illustrates the corrected control flow; it does not replace the full XLSX parser.

Inspect the independent metadata validator · Python
def validate_metadata(first, second, requested_sunday=None):
    # A manually selected date must never bypass source metadata checks.
    for field in ("exported_at", "company", "station", "start_date"):
        if not first.get(field) or first[field] != second.get(field):
            raise ValueError(f"Missing or conflicting {field}")
    datetime.fromisoformat(first["exported_at"])
    if first["station"] != "DEMO":
        raise ValueError("Unexpected example station")
    sunday = date.fromisoformat(first["start_date"])
    if sunday.weekday() != 6:
        raise ValueError("Schedule must start on Sunday")
    if requested_sunday and date.fromisoformat(requested_sunday) != sunday:
        raise ValueError("Selected Sunday differs from source week")
    return [str(sunday + timedelta(days=i)) for i in range(7)]
Inspect the read-only Access export adaptation · PowerShell

Adapted from the project’s DAO read-only export and source-fingerprint checks. Company-specific table filters were replaced by an explicit allowlist. Syntax checked; actual DAO/Access execution was not exercised in this portfolio task.

# Adapted example of the application's read-only Access export pattern.
# Requires Windows and DAO.DBEngine.120. Syntax checked; Access execution untested.
# Example: supply a disposable Access file and an explicit table allowlist.
param(
    [Parameter(Mandatory=$true)][string]$Source,
    [Parameter(Mandatory=$true)][string]$Destination,
    [Parameter(Mandatory=$true)][string[]]$Tables
)
$ErrorActionPreference = 'Stop'
$sourcePath = [IO.Path]::GetFullPath($Source)
$destinationPath = [IO.Path]::GetFullPath($Destination)
if ([IO.Path]::GetExtension($sourcePath) -ne '.accdb' -or
    [IO.Path]::GetExtension($destinationPath) -ne '.json' -or
    $sourcePath -eq $destinationPath) { throw 'Choose separate Access and JSON paths.' }
foreach ($name in $Tables) {
    if ($name -notmatch '^[A-Za-z_][A-Za-z0-9_]*$') { throw 'Unsupported example table name.' }
}
$before = (Get-FileHash -LiteralPath $sourcePath -Algorithm SHA256).Hash
$engine = New-Object -ComObject DAO.DBEngine.120
$database = $engine.OpenDatabase($sourcePath, $false, $true) # Read-only flag.
$output = [ordered]@{sourceSHA256=$before; tables=[ordered]@{}}
try {
    foreach ($name in $Tables) {
        $records = $database.OpenRecordset(('SELECT * FROM [' + $name + ']'), 4)
        $rows = [Collections.Generic.List[object]]::new()
        try {
            while (-not $records.EOF) {
                $row = [ordered]@{}
                foreach ($field in $records.Fields) {
                    $value = $field.Value
                    if ($value -is [DBNull]) { $value = $null }
                    if ($value -is [datetime]) { $value = $value.ToString('o') }
                    $row[$field.Name] = $value
                }
                $rows.Add($row)
                $records.MoveNext()
            }
        } finally { $records.Close() }
        $output.tables[$name] = @($rows.ToArray())
    }
} finally { $database.Close() }
if ((Get-FileHash -LiteralPath $sourcePath -Algorithm SHA256).Hash -ne $before) {
    throw 'Source changed during read; export rejected.'
}
$output | ConvertTo-Json -Depth 12 | Set-Content -LiteralPath $destinationPath -Encoding UTF8

CASE A / SCHEDULE METADATA

Explicit dates must not bypass validation

Requirement
Both schedule worksheets must agree on source metadata, even when a Sunday is supplied manually.
Reproduced defect
A manufactured workbook with conflicting station metadata was rejected by the inferred-date path but accepted by an explicit-Sunday first import into a disposable database.
Correction
The parser was changed to always validate metadata, preserve the export timestamp, derive the reporting year from that metadata, and compare the selected Sunday with the source week.
Observed verification
A copy of the installed corrected parser rejected the mismatch in both paths. All 14 malformed-workbook cases also rejected on the explicit-date path. Valid explicit-date first and newer imports succeeded with retained timestamps.
Preservation checks
Rejected or stale inputs left the manufactured database, page and history unchanged. Source code hashes remained unchanged during verification; the workbook parser was not mocked.

This establishes the on-disk correction and its isolated verification. It does not establish that a running service had reloaded that version or that real business records were affected by the original gap.
